# 顺言本机服务协议（首轮契约）

> 版本：`v1`；供 `web/` PWA 与 `host/` 服务共同实现。仅限本机/局域网配对控制。

## 1. 传输与认证

- HTTPS JSON API：`/api/v1/...`。手机麦克风权限要求安全上下文；HTTP 局域网访问不得被当作可用音频链路。
- 所有配对后的请求使用 `Authorization: Bearer <sessionToken>`。会话令牌由主机加密安全随机数生成，只在配对响应中返回；禁止放进 URL、日志或 UI 截图。
- 主机配对码由主机端生成，短时有效且单次使用。`GET pairing-code` 读取当前有效码；不存在有效码时返回 `{ "pairCode":null, "expiresIn":0, "singleUse":true, "available":false }`。电脑本机显式 rotate 才生成新码并作废旧码。认证失败统一返回 `401`，来源被拒绝返回 `403`。
- API 不记录音频数据、配对码、令牌或 Codex 对话正文。公网暴露与匿名配对禁止。

## 2. 通用请求/响应

请求 JSON 使用 UTF-8。会改变按键或配置状态的请求带 `requestId`（UUID）；服务端对短时间重复 ID 返回相同结果或忽略重复操作。

成功：`{"ok":true,"data":{...}}`

失败：`{"ok":false,"error":{"code":"NOT_PAIRED","message":"请先配对本机服务"}}`

控制页每 2 秒调用一次已认证的 `GET /api/v1/status` 作为会话心跳；主机连续 6 秒未收到该会话请求时，会停止活动的点按录音状态并释放按键。按住说话期间客户端每 1 秒发送一次同一语音键 `press` 续租；主机 3 秒未收到续租即释放长按键，普通状态心跳不延长长按。恢复连接后须由用户重新触发，不自动补发按键。

## 3. 端点

| 方法与路径 | 认证 | 用途 |
|---|---|---|
| `GET /api/v1/health` | 否 | 返回服务版本、平台、配对可用状态，不返回密钥 |
| `GET /api/v1/pairing-code` | 仅本机 | 电脑本机配对页读取当前动态配对码；只允许 loopback 或本机绑定网卡地址，拒绝其他局域网客户端 |
| `POST /api/v1/pairing-code/rotate` | 仅本机 | 电脑本机配对页显式生成新码并立即作废旧码，返回 `{ "pairCode":"123456", "expiresIn":300, "singleUse":true, "available":true }` |
| `POST /api/v1/pair` | 否（配对码） | 请求 `{ "pairCode":"123456" }`；成功返回 `{ "sessionToken":"…","host":{"platform":"windows|macos","label":"…"} }`，配对码立即失效 |
| `GET /api/v1/config` | 是 | 读取用户配置 |
| `PUT /api/v1/config` | 是 | 保存 `{ "requestId":"uuid", "config":{...配置字段...} }` |
| `POST /api/v1/control` | 是 | 发送键盘 tap/press/release 操作 |
| `POST /api/v1/control/release-all` | 是 | 释放所有活动键；断线/异常回收的幂等兜底 |
| `GET /api/v1/status` | 是 | 获取平台授权、连接和 Codex 摘要状态；未知状态使用 `unknown`，不可伪报实时 |
| `GET /api/v1/local-status` | 仅运行服务的本机地址/loopback | 电脑端只读观察已配对控制端，不依赖电脑浏览器自身持有手机令牌；不续租控制端心跳，不返回令牌、配对码或对话 |
| `GET /api/v1/audio/devices` | 是 | 列出可用的音频播放端，供用户选择虚拟音频线的播放端 |
| `POST /api/v1/audio/start` | 是 | 启动已选择的音频播放端；请求 `{ "sampleRate": 48000 }` |
| `POST /api/v1/audio/chunk` | 是 | 发送带 `X-Audio-Sequence` 的有界 `application/octet-stream`、单声道 PCM16 little-endian 音频分片 |
| `POST /api/v1/audio/stop` | 是 | 停止当前配对会话的音频转接 |

## 4. 控制操作

```json
{
  "requestId": "uuid",
  "button": "voice|confirm|cancel",
  "phase": "tap|press|release",
}
```

- `tap` 对完整映射发送一次按下/释放。
- `press` 按修饰键到主键顺序按下并记录活动键；`release` 对应逆序释放。所有按键有主机侧超时回收。
- 映射只从主机已保存配置读取；控制请求不可临时指定键名。映射为一到五个允许的语义键名；主键必须位于最后。拒绝任意文本键名、未知键或危险注入参数。
- `phase` 重复 `press`、不存在的 `release` 均按幂等处理，且不会让其他会话释放彼此的按键。

`toggle` 模式下，PWA 每次短按语音键都发送 `phase: "tap"`；主机串行切换状态，按配置在 `voiceStart` 与 `voiceStop` 中交替执行，并在响应中返回当前语音状态，重复 `requestId` 不会二次切换。`hold` 模式下，PWA 在 pointer down 请求 `press`，pointer up/cancel 请求 `release`，主机按下/释放 `voiceStart` 映射。确认和取消使用 `tap`。页面 `visibilitychange`、`pagehide`、断线和按键触摸取消都触发 `release-all`；主机收到释放请求或检测到 toggle 会话超时后，也会尝试发送已配置的 `voiceStop`，再释放活动按键。

## 5. 配置字段

```json
{
  "voiceMode": "toggle|hold",
  "mappings": {
    "voiceStart": ["ALT_RIGHT"],
    "voiceStop": ["ALT_RIGHT"],
    "confirm": ["ENTER"],
    "cancel": ["ESC"]
  },
  "appearance": {
    "keyStyle": "soft|glass|solid",
    "keyRadius": 22,
    "keys": {
      "voice": {"icon":"mic","iconData":null,"color":"#d9e7ed","glow":"#a9d9f5"},
      "confirm": {"icon":"check","iconData":null,"color":"#d9e7ed","glow":"#a9e6ce"},
      "cancel": {"icon":"x","iconData":null,"color":"#d9e7ed","glow":"#f1afbb"}
    }
  },
  "audio": {"outputDeviceId": null}
}
```

实际实现必须限制颜色格式、圆角范围、图标标识与映射长度；不接受任意 HTML、脚本、SVG 或远程图标 URL。`icon` 首版从内置图标名中选择，或在上传图标时设置为 `custom`；`custom` 必须伴随有效的 `iconData`。`iconData` 仅接受用户上传的 PNG/WebP data URL，单张不超过 256 KiB。客户端与主机都要验证 MIME 类型、文件签名和大小，不直接插入 HTML；自定义图片使用等比缩放并在重置时清除。

## 6. 状态模型

状态屏摘要状态：`idle | working | waiting | completed | error | offline | unknown`。字段为 `{state, title, detail, updatedAt, source}`。默认不返回对话正文；`detail` 限长度且只用于无敏感内容的简短提示。没有可验证的 Codex 事件源时返回 `unknown` 或 `offline`。

## 7. 平台按键适配器接口

服务内部适配器统一提供 `press_key(name)`, `release_key(name)`, `tap(keys)`, `release_all()`, `permission_status()`。Windows 使用系统键盘事件 API；macOS 使用 CoreGraphics 键盘事件并遵循系统权限。macOS 未授权时动作返回 `PLATFORM_PERMISSION_REQUIRED`，状态报告授权不足，不绕过系统权限。

### 音频转接（首轮试验协议）

- 手机网页由用户点按语音键后，通过 HTTPS 安全上下文和 `getUserMedia()` 请求手机麦克风授权。浏览器授权状态由手机浏览器决定，本机服务的 `microphoneAvailable` 为 `null`，不能代表手机权限。
- 前端使用 AudioWorklet 采样为 8–96 kHz、单声道 PCM16 little-endian，每约 100 ms 发送一个二进制分片；每片不超过 24 KiB，并以 `X-Audio-Sequence` 强制递增。主机限制每片大小、格式、顺序及当前连接会话，音频只驻留在内存，不写盘或写日志。
- 主机使用 `sounddevice`/PortAudio 将 PCM 播放到用户明确选择的虚拟音频设备播放端。未选设备时拒绝启动，不默认把手机声音放到物理扬声器。语音输入软件需选择同一条虚拟音频线的录音端；Windows VB-CABLE 的输入/输出名称和 macOS 虚拟设备的名称应按驱动实际枚举结果确认。
- 语音停止、取消、断开、服务释放或 3 秒没有新音频分片时停止播放并关闭流。序号错乱后必须重启音频会话，不重放旧音频。
- HTTP 小分片是当前实现的低依赖原型，不视为已完成实时语音验收。Windows 与 macOS 及 iOS Safari/Android Chrome 需测端到端延迟、长时间抖动、页面前后台行为和设备恢复；如结果不满足语音输入要求，再迁移 WebSocket/WebRTC。
