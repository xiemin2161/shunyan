# 电脑端手动重启服务

用户明确要求由自己点击重启。功能配置底部已增加“本机服务 / 重启服务”，只在运行服务的本机电脑启用，手机不显示。

## 新后台

POST `/api/v1/service/restart` 只允许本机、可信Host/Origin、空JSON请求；不接受命令、端口或路径参数。录音、音频转接或按键未释放时拒绝。先同步设备并备份config、配对、Codex绑定；备份失败不重启。请求幂等，准备后拒绝新控制请求；响应返回后关闭8765、证书辅助服务及音频，再以原Python和原参数替换当前进程，保留原地址与证书。健康接口新增instanceId和restartAvailable供页面确认新实例恢复。

## 旧后台首次启用

当前54820/0.2.0不包含新重启接口，网页无法直接让旧代码认识新API。页面点击“重启服务”会显示首次启用对话框，提供原主机专用VBS启动器。用户自行下载并双击后，以pythonw隐藏运行项目tools/restart_current_service.pyw。

首次启动器会核对唯一8765顺言Pythonw进程和原参数，使用原公开证书严格验证HTTPS状态、检查没有录音、备份配置，再由用户发起的本地动作替换旧进程，等待原端口释放后启动新服务。不会修改信任设置、绕过证书检查、改变执行策略或启动其它端口；不重启电脑。首次运行前需松开所有按键。启动器明确绑定当前Windows项目路径，不宣称是其它主机的通用发布包。

## 验证与边界

99项Python测试通过，包含本机鉴权、恶意参数和跨来源拒绝、录音或按键阻塞、备份失败不重启、重复请求只调度一次以及首次启动器录音时不会终止进程。JS语法通过。实际浏览器确认按钮与旧版首次启用对话框可用，启动器从8765下载内容哈希一致。

没有由开发工具执行重启启动器或调用真实重启API；当前仍是旧进程，等待用户手动执行首次启动器。测试中的重启回调和进程终止全部为模拟，不能当作真实重启验收。
