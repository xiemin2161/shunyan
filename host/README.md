# 本机服务开发说明

当前本机服务提供同源静态网页托管、一次性配对、配置读写、系统键盘事件、受限 PCM 音频转接和状态摘要 API。手机端已有采音推流前端，真实手机至目标语音软件的音频仍需实机验收；Codex 实际状态通过只读本机会话事件组件接入。只有装有兼容的虚拟音频设备并明确选择输出端后，音频路由才可启动。

## 本机开发启动

在仓库根目录运行：

先安装本机音频后端依赖：

```powershell
python -m pip install -r host/requirements.txt
```

Windows PowerShell：

```powershell
python -m host.server
```

macOS 终端：

```sh
python3 -m host.server
```

默认仅监听 `127.0.0.1:8765`。桌面浏览器打开 `http://127.0.0.1:8765/` 可访问网页。启用局域网访问后，电脑本机请使用服务自己的绑定地址打开 `/pairing.html`，例如 `https://192.168.1.20:8765/pairing.html`；配对页读取当前有效码，点击“换一组”会调用 loopback/本机地址保护的轮换接口。其他局域网设备不能读取或轮换配对码。

手机访问前，需要在电脑的私有局域网 IP 上启动服务，并配置手机信任、且证书名称匹配服务绑定地址的 TLS 证书：

```powershell
python -m host.server --host 192.168.1.20 --port 8765 --tls-cert .\local-cert.pem --tls-key .\local-key.pem
```

服务拒绝绑定公网 IP、通配地址和组播地址。没有 TLS 时，局域网配对和持有令牌的控制请求会返回 `HTTPS_REQUIRED`；HTTP 只适用于本机预览。开发/发布启动器应以后使用 Windows 隐藏窗口启动方式或 macOS 登录项，当前没有启动后台进程。

### 手机扫码与公开证书下载

设置页根据浏览器信息自动识别电脑或手机/平板（包括桌面模式 iPad），与窗口宽度分开，不再提供设备模式选择。电脑负责主机配置，手机只展示连接、证书和麦克风准备；展示识别不改变本机权限校验。

- 在运行服务的电脑打开 `/settings.html#connection`，展示单次有效的连接二维码；手动刷新会轮换配对码。扫码打开链接后自动配对，六位配对码只在 URL 片段中传递，服务访问日志不接收该片段。
- 手机设置页支持摄像头扫码和从图片识别，解码在浏览器本地进行。切换设置页、关闭扫码或离开页面会关闭摄像头并取消未完成的图片识别。仍支持手输配对码。
- 用 `--trust-cert /path/to/root.cer` 指定要给手机信任的公开根证书（自签部署也可提供对应公开证书）；`/certificate.cer` 仅提供该公开证书的 DER 内容，拒绝私钥、尾随内容和多证书混合文件，不公开 TLS 私钥路径。
- 可额外指定 `--cert-port 8766`：在相同私有地址开启仅提供证书下载页和公开证书文件的 HTTP 入口。手机直接打开此地址下载，不再提供证书二维码；此入口没有配对、控制、静态文件或音频 API，主服务仍要求 HTTPS。
- 苹果移动设备自动使用 `/certificate.mobileconfig`，返回 `application/x-apple-aspen-config`，通过普通链接直接交给 Safari 的原生描述文件处理，不经过 fetch/Blob 或 HTML download 属性。配置文件只包含当前公开根证书，不含 MDM、VPN、代理、私钥或系统自动信任指令；安卓及其他设备继续下载 `.cer`。
- iOS/iPadOS 下载后必须由用户到“设置 → 已下载描述文件”（或“通用 → VPN 与设备管理”）安装，再到“通用 → 关于本机 → 证书信任设置”开启完全信任。网页无法自动打开安装完成流程或开启信任。苹果入口优先使用独立证书 HTTP 服务，避免首次访问 HTTPS 尚未信任证书造成安装下载被阻断。
- 不配置 `--trust-cert` 时，页面明确显示证书未配置，不提供失效下载链接；正式受信 HTTPS 部署不必让手机安装本地证书。

例如在前述 TLS 启动参数后添加 `--trust-cert ./phone-root.cer --cert-port 8766`。Windows 后台启动必须用 `pythonw` 或隐藏窗口，不能因接入证书服务弹出终端。手机系统证书安装与摄像头权限由用户完成，网页不会自动安装证书或开启系统信任。

音频转接将主机端 PCM 播放到设置页选定的虚拟音频播放端；语音软件需选择同一虚拟线对应的录音端。服务不会自动安装驱动，也不会默认向物理扬声器播放。Windows/macOS 均需先安装用户选择的虚拟音频设备，完整说明和验收仍在进行。

## 配置与数据边界

电脑设置页每两秒读取仅本机可访问的 `/api/v1/local-status`，展示控制端的真实配对/最近在线状态。已配对且十秒内有认证请求显示已连接，超过十秒仍保留已配对，但不宣称在线。电脑观察请求不更新手机最后活动时间、不取得手机会话令牌，不能据此发送控制命令；手机仍通过原有 Bearer 会话访问 `/api/v1/status`。手机会话失效时清除旧会话并显示重新配对；旧请求的迟到响应不能覆盖新会话。

手机配对、主机服务与 Codex 事件源是独立状态。PC 后台可安装只读本机会话连接组件，从当前用户的 Codex SQLite 元数据和受限本地事件尾部读取状态。组件未安装或源不可用时明确显示未接入，不因手机配对成功而伪造 Codex 已连接。用户授权后可显示本机运行中根对话的标题，不读取对话正文或认证文件。

- 配置保存于当前用户配置目录，采用原子替换；配对会话令牌只保存在进程内存，服务重启后需重新配对。
- 配对码通过 loopback 或主机本机绑定地址读取/轮换；五分钟内有效、成功配对后立即失效，并按来源限速。
- 组合键由服务端依据已保存配置解析；修饰键先按下、主键后按下，按相反顺序释放。长按按键需要每秒续租，3 秒没有 press 续租就释放；toggle 语音在会话 6 秒无请求后发送一次 voiceStop。
- 本服务不写请求日志，不记录配对码、会话令牌、音频或 Codex 对话正文。
# 当前正式发布约定

Windows本机正式入口固定为 `https://192.168.50.200:8765`，证书引导端口8766。每次更新在保留设置、Codex绑定、配对记录和证书后替换原进程，只运行一个正式实例。不能以另开正式端口代替更新。当前组件1.1.0读取官方会话标题索引并修复Windows扩展路径发现；原1.0.0安装绑定兼容保留。

`--config-dir`仅用于明确指定的隔离配置场景，默认仍沿用当前用户配置，不意味着可以并行发布新旧正式实例。
